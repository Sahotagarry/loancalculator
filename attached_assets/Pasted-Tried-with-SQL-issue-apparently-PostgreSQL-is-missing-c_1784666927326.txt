2. Create a one-time database push workflow
In GitHub, go to the repo root and choose:
 
 
 
 
Plain Text
 
Add file → Create new file

Show more lines
 
File name:
 
 
 
 
Plain Text
 
.github/workflows/db-push.yml

Show more lines
 
Paste this:
 
 
 
 
YAML
 
name: Create database tables


on:

  workflow_dispatch:


jobs:

  db-push:

    runs-on: ubuntu-latest


    steps:

      - name: Checkout code

        uses: actions/checkout@v4


      - name: Setup pnpm

        uses: pnpm/action-setup@v4

        with:

          version: 10


      - name: Setup Node.js

        uses: actions/setup-node@v4

        with:

          node-version: 22

          cache: pnpm


      - name: Install dependencies

        run: pnpm install --frozen-lockfile


      - name: Push database schema

        env:

          DATABASE_URL: ${{ secrets.DATABASE_URL }}

        run: yes | pnpm --filter @workspace/db run push

Show more lines

Why this is the right approach
Your Azure app is already live and working. The client creation failure is because PostgreSQL is missing the clients table, not because of Azure deployment anymore. Running the schema push from GitHub Actions avoids the Windows sh / @esbuild/win32-x64 problem you keep hitting locally.
One caution: since the database password has appeared in the chat/screenshots, I strongly recommend rotating the PostgreSQL admin password after the setup is complete, then updating DATABASE_URL in both Azure App Service and GitHub Secrets.
